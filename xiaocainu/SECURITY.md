## 一、三维安全（3D Security）总览

```
┌─────────────────────────────────────────────────────────────┐
│  维度 1 · 边界防御 Perimeter Defense  （M5 契约层 + M7 语义层） │
│   ├─ 入口 JSON 契约（pydantic 长度/类型/数值边界）            │
│   ├─ 输入净化 sanitize_text（控制字符/空字节剥离、超长截断）  │
│   ├─ prompt 注入拦截 check_injection（精确签名拒绝）         │
│   └─ 频率节流 RateLimiter（按会话滑动窗口）                  │
├─────────────────────────────────────────────────────────────┤
│  维度 2 · 凭证隔离 Credential Isolation                       │
│   ├─ Agnes / 飞书密钥 仅服务端 .env 读取，永不下发前端        │
│   ├─ 前端只连本网关，不直接持任何 token / app_secret          │
│   └─ 错误信息不回显密钥；飞书失败仅返回 code/msg 不含密钥     │
├─────────────────────────────────────────────────────────────┤
│  维度 3 · 数据最小化 Data Minimization                       │
│   ├─ 对话上下文 仅内存级 SessionStore（TTL 过期、不落库）     │
│   ├─ 不持久化任何聊天记录 / 个人财务 PII                     │
│   └─ 飞书写回仅存业务必要字段（不含工号、不含密钥、单号只读） │
└─────────────────────────────────────────────────────────────┘
```

## 二、维度 1 · 边界防御（入口两道闸）

### 第 1 道闸：JSON 契约（M5 · pydantic）
请求模型即「契约」，在 HTTP 边界即拒绝非法输入：

| 字段 | 约束 | 防御点 |
|------|------|--------|
| `ChatRequest.text` | `min_length=1, max_length=2000` | 防空 / 超长 payload |
| `ReimburseRequest.amount` | `ge=0, le=10_000_000` | 防越界数值 / 负数 |
| 各字符串字段 | `max_length=…`（16/32/200） | 防字段膨胀 |

> 越界/超长会被 FastAPI 直接返回 **422**，连业务逻辑都不进入。

### 第 2 道闸：语义层守卫（M7 · `security/guard.py`，纯 stdlib）
在 `dispatch("/chat")` 真正调用 Agent **之前**依次执行：

1. **`sanitize_text(text)`** —— 剥离 NUL 空字节、非允许控制字符（含 `\r \f \v \b`）、
   去首尾空白、超长截断到 2000。**防御纵深**，即使绕过契约层也能净化脏字符。
2. **`check_injection(text)`** —— 精确 prompt-injection 签名拦截（如
   `忽略上面的`、`ignore previous`、`system prompt`、`jailbreak` 等多字短语）。
   命中即返回 **400**，**绝不进入 LLM**，杜绝越权/套取系统提示。
3. **`RateLimiter.allow(sid)`** —— 按 `session_id` 滑动窗口（默认 60s / 30 次）限流。
   触发返回 **429**，防刷接口 / 模型费用失控 / 资源耗尽。

> 设计取舍：注入拦截采用「精确签名 + 大小写不敏感子串」而非模糊匹配，
> 以**避免中文报销语境下的误报**（正常报销话术几乎不会命中这些短语），
> 同时保证零漏检已知注入套路。

### 第 3 道闸：图片入口防线（M9 · `api/main.py` + `models/ocr.py`）
发票图片是新引入的二进制入口，`sanitize_text`/`check_injection` 对其不适用，
故为 `/ocr` 与 `/chat.image_b64` 单独构筑图片专用闸：

1. **base64 合法性**：`b64decode(validate=True)`，非法编码直接 400（大声报错不静默兜底）。
2. **字节上限**：默认 8MB（`OCR_MAX_IMAGE_MB`），超限 400/413，防资源耗尽。
3. **魔数白名单**：按**真实文件头**判定 JPEG(`FF D8 FF`)/PNG(`89 50 4E 47`)/GIF/WebP(`RIFF…WEBP`)，
   不信任扩展名与声明 MIME——伪装成图片的其他文件在此被拒。
4. **extraction-only prompt**：OCR 引擎使用固定抽取 prompt（只输出 JSON），
   发票内印刷文字即使携带注入指令，也只被当作「待抽取文本」而非指令；
   输出经 `sanitize_fields` **字段白名单强校验**（金额范围/类型城市枚举/长度截断），
   非白名单内容不进入任何写库路径。
5. **独立限流**：`OCR_LIMITER`（60s/10 次，按会话）单独限流视觉调用，防模型费用失控。
6. **占位 key 防护**：形如「你的密钥_勿提交」的模板值视为未配置，装配层直接 503，
   **绝不拿占位凭证发起真实调用**（零试探、零隐性计费）。

## 三、维度 2 · 凭证隔离

| 项 | 做法 |
|----|------|
| 模型密钥（Agnes `OPENAI_API_KEY` 等） | 仅 `models/llm.py` 的 `from_env()` 在服务端读取；绝不出现在前端或日志 |
| 飞书 `app_id` / `app_secret` | 仅 `models/feishu.py` 的 `from_env()` 服务端读取 |
| 前端 | 只连同源 `/chat`、`/reimburse`、`/progress`，**不持有任何 token** |
| 错误回显 | 飞书失败仅返回 `code/msg` 文本，不含 `app_secret`；Agnes 异常不回显密钥 |
| 凭证文件 | `.env` 已被 `.gitignore` 忽略，不会随源码提交 |

## 四、维度 3 · 数据最小化

- **对话不落库**：`api/session.py` 的 `SessionStore` 为**进程内内存字典**，
  带 TTL（默认 30 分钟）自动过期，**不写数据库、不写文件、不对外可查**。
  敏感财务信息（姓名/金额/部门）仅在内存驻留，进程重启即消失。
- **不持久化聊天记录**：经与赛题需求评估，后台「全量对话可查看」**非必要**，
  反而放大 PII 泄露面；故采用内存级会话，**不囤积数据 = 隐私优先**（可作 PPT 安全亮点）。
- **飞书写回极简**：`build_reimbursement_record` 仅写入业务必要字段，
  **不写「工号」、不写「单号」（AutoNumber 只读）、不写任何密钥**；
  返回前端前经 `public_view()` 屏蔽 `record_id` 等内部键。
- **发票图片仅内存中转（M9）**：上传的发票图从 base64 解码到上传飞书全程只在内存，
  **不写本地磁盘、不进日志**；发票原件最终存于**用户自己的飞书表附件列**
  （数据主权在用户侧，网关不囤积 PII）；OCR 结果仅保留白名单业务字段，
  图片其余视觉内容不落任何存储。

> 可选增强（**不进主干**，仅作 PPT「未来小想法」）：若赛题要求合规审计，
> 可加「脱敏 + 加密 + 留存期限 + 权限分级」的审计日志，作为可插拔模块单独评估。
